# Vetro

Nuxt 4 + Supabase. Для локального запуска нужен Node.js 24.15 или новее в ветке 24.

```sh
npm ci
npm run dev
```

## Данные и кеширование

- `app/plugins/vue-query.ts` создаёт TanStack QueryClient отдельно для каждого SSR-запроса. В HTML передаются только успешные публичные запросы. Браузер восстанавливает кеш без повторной загрузки при гидратации.
- Все публичные данные загружаются через `useSiteQuery`. Ключ — `['site', URL]`; для изменяемых props передавайте функцию URL. Данные свежие 60 секунд; неиспользуемый кеш удаляется через 10 минут. Одновременные запросы объединяются. Возврат фокуса не вызывает загрузку, восстановление соединения и повторный вход на страницу обновляют устаревшие данные.
- Резервный контент `default` отображается при недоступности API и не записывается в кеш как успешный ответ. GET повторяется максимум один раз в браузере при сетевой ошибке/5xx; SSR и ошибки 4xx не повторяются.
- `definePublicContentHandler` кеширует успешный результат публичного API на сервере на 60 секунд, до 256 URL на процесс. Запросы с одинаковым URL объединяются. Ошибки не кешируются. HTTP-ответы используют `no-store`, чтобы браузер и CDN не сохраняли отдельную устаревшую копию.
- `defineContentMutationHandler` сбрасывает серверный кеш после успешной записи. Сброс общий: публикация услуги или объекта влияет на несколько связанных API. Прямые изменения в Supabase становятся видны после истечения TTL; открытая страница обновляет данные при следующем запросе.
- Админка выполняет записи через TanStack `useMutation`, без повторов. После успеха отменяются старые запросы и инвалидируется клиентский кеш. Другие вкладки получают уведомление через BroadcastChannel. Незавершённый старый серверный запрос не может вернуть устаревшую запись в кеш после публикации.
- Защищённые GET-запросы имеют ключ `['admin', userId, URL]`, объединяют одновременные загрузки и всегда проверяют актуальную ревизию при явном открытии/перезагрузке редактора. Выход удаляет приватный кеш. Авторизация и проверка прав на сервере выполняются на каждый защищённый запрос.
- Supabase service-role клиент переиспользуется только на сервере, без сохранения пользовательских сессий. Общий серверный кеш содержит только ответы публичного API.

Серверный кеш рассчитан на текущий запуск одного экземпляра приложения в Docker Compose. При нескольких репликах нужен общий кеш и межпроцессный сброс (например, Redis); текущая инвалидация действует внутри одного процесса. Перезапуск очищает кеш. Отдельный Node.js backend не требуется: API обслуживает Nitro.

Новые публичные API оборачивайте в `definePublicContentHandler`, записи — в `defineContentMutationHandler`. Не используйте общий кеш для `/api/admin/**`, авторизации и проверки здоровья.
